# 10분 모델의 시간대별 페이스 환산 한계 분석 (Issue #19)

> **이 문서는 정확도 검증이 아니다.** 시간대별 실제 승패 데이터가 없어서, 환산한 입력이 학습 분포에서 얼마나 벗어나는지(분포 이탈)와 킬 1개가 승률을 얼마나 움직이는지(민감도)만 잰다. t분 점수판은 아래 성장 가정으로 만든 것이라, 수치는 방향과 크기를 보는 용도다.

- 모델: m2 조건(DATA_N 5000·DATA_SEED 1, 실서버 m20261118-2 와 같은 학습 조건으로 다시 학습). 승률은 sklearn 파이프라인(서빙 ONNX 와 오차 1e-4 이하) 출력
- 학습 분포: `data/high_diamond_ranked_10min.csv` 9,879경기(팀 값은 두 팀을 합친 19,758행)의 1~99% 분위수
- 환산: `client/bridge.py`의 `scale_to_ten_minutes` 그대로(누적 값 × 10/t, 0.5 올림, 허용 범위로 자름, 레벨은 그대로)
- 다시 만들기: `uv run --group train python -m training.pace_scaling`

## 2. 성장 가정 (t분 점수판을 만드는 방법)

| 지표 | 가정 |
|---|---|
| 킬·어시스트 | 10분 값 × (t/10)^1.3 (뒤로 갈수록 교전이 잦다) |
| CS | 10분 값 × (t − 1.1)/(10 − 1.1) (첫 미니언 1:05 무렵) |
| 평균 레벨 | 10분 값 + (중앙값 곡선 t분 − 7.0). 곡선 5분 4.9, 10분 7.0, 15분 9.9, 20분 11.9, 25분 13.4. 두 팀 레벨 차이는 그대로 |
| 드래곤·전령·포탑 | 5분은 0. 15·20·25분은 10분 값에 두 팀 합계 15분 드래곤 1·전령 1·포탑 2; 20분 드래곤 2·전령 1·포탑 6; 25분 드래곤 3·전령 1·포탑 10를 킬 몫으로 나눠 더한다 |
| 대표 판(10분 기준) | 접전: 두 팀 킬 6·어시 6·CS 269·레벨 7.0. 우세: 킬 8:5·어시 9:5·CS 285:255·레벨 7.3:6.8·드래곤 1:0. 열세는 우세를 뒤집은 것 |
| 데모 | `api/static/overlay.html`의 세 데모 점수판 그대로(06:30·14:20·23:10) |

## 7. 결론

1. **10분 환산은 10분 근처에서만 학습 분포 안에 있다.** 환산은 누적 값만 바꾸고 평균 레벨은 그대로 둔다. 그래서 팀 평균 레벨이 학습 1~99%(6.2~7.6) 밖인 비율이 8분 72.5%, 12분 92.0%, 15분 이후 100.0%다. 모델 입력은 레벨 차이라 차이 자체는 범위 안에 남지만, 학습 때 본 적 없는 레벨대의 경기를 같은 계수로 읽는다.
2. **초반에는 킬 1개가 과장된다.** 킬 +1의 승률 변화가 10분의 ×2.19(5:00), ×1.58(7:00), ×1.24(8:00)이다. 1.5배를 넘는 7:00까지를 초반 경고 구간으로, 경계를 7:30으로 둔다.
3. **중후반에는 킬 1개가 반영되지 않거나 한 번에 뛴다.** 배율이 1보다 작아 반올림 뒤 값이 그대로인 경기가 12분 19.7%, 15분 30.7%, 20분 49.8%다. 승률이 계단처럼 움직인다.
4. **20분 이후에는 모델 입력(포탑 차이)도 범위를 벗어난다.** 포탑 차이 이탈이 20분 14.1%, 25분 31.1%다.
5. **경고 기준** (AGENTS.md 3-4절 "시각 경고"에 적고 `client/bridge.py`·`/overlay`에 넣었다): 7:30 전 `early`(배율과 "킬 1개가 10분보다 크게 반영"), 12:00부터 `late`("10분 모델 범위 밖(레벨), 승률은 참고만"), 20:00부터 `very_late`("포탑 차이도 범위 밖, 우세·열세 방향만"). 7:30~12:00에는 경고를 내지 않는다.
6. **발표 문구**: "게임 중 전 구간에서 정확하다"고 말하지 않는다. "10분 근처(7:30~12:00)에서 학습 분포 안, 그 밖은 경고와 함께 방향만 보여 준다"고 말한다.

**한계**: t분 점수판은 2절의 성장 가정으로 만든 것이다. 실제 시간대별 점수판·승패가 모이면(전적 DB 의 `game_time_sec`, AGENTS.md 3-5절) 같은 표를 실측으로 다시 만든다. 이 분석은 정확도를 재지 않는다.
