② 합법 공개 데이터와 네 가지 코칭

점수판 공개 값 8개로, 네 가지를 알려 준다

첫 킬킬어시스트CS평균 레벨드래곤전령포탑 상대 골드와드위치쿨다운

학습 모델 입력은 이 8개뿐. 인게임 HUD 는 여기에 공개 아이템·사망 타이머·내 보유 골드를 더해 실시간 판세를 따로 계산한다. Riot 공식 로컬 API 의 점수판·이벤트만 쓰고, 랭크 게임 중에는 쓰지 않는다(연습·AI 대전·리플레이).

1 페이스 진단

2 격차 원인

3 다음 3분 목표

채우면 승률이 가장 많이 오르는 수치

③ 왜 이 구조인가

설계 이유 다섯 가지

1

규칙 먼저 · 게이트 통과만

아이템·스킬은 규칙표, 승률만 모델. 딥러닝(0.1837)은 로지스틱(0.1824)보다 나쁘고 설명이 어려워 제외

Brier 0.1824 < 0.1917
2

정규화 내장 ONNX

학습·서빙 계산 차이를 없애고 서버에 학습 라이브러리를 안 깐다

오차 1.19e-07이미지 430MB
3

코드 판 · 모델 판 분리

v1.0 과 mYYYYMMDD-N. 패치 날엔 이미지 없이 모델만 교체

baked → m…-1 → m…-2
4

키 없는 배포

서버 안 러너, EC2 는 OIDC, 파일은 잡 출력으로. 저장소에 키 0개

SSH·AWS 키 0
5

즉시 되돌리기 · 한계 실측

옛 판을 버킷에 남겨 재학습 없이 복구. 교체 중 1.5~4.2초 끊김을 실측해 "무중단"이라 쓰지 않음

롤백 실측 16초
④ AI를 계약과 게이트로 통제

기준은 사람이, 통과는 AI가. 그리고 실제로 막았다

사람이 먼저 정한 것AI 도구가 구현한 것
입력 8개, 422 거절 규칙, 요인·목표 계산 정의API, 브리지, 시각 화면
게이트(Brier·LogLoss·정확도 0.68), Parity 1e-4 · 23건학습·변환·대조 시험 코드
판 이름, 키 없는 원칙, 자동 복구 조건워크플로, server.sh, 로컬 E2E

테스트 정답은 코드 출력을 베끼지 않고 계약에서 손으로 계산. 일부러 심은 버그 3 / 3 검출, 자동 테스트 449 passed

LLM 은 문장만, 숫자는 계산 결과만

  • 브리핑의 숫자를 모두 뽑아 응답 JSON 에 있는 값인지 검사
  • 인게임 로컬 LLM 브리핑도 같은 검사기: "3초 내 제압" 같은 근거 없는 수치, "곡괭이로 방어력" 같은 아이템 오기는 버리고 규칙 문장으로
  • 답마다 model_version 을 남겨 어느 판의 계산인지 추적
